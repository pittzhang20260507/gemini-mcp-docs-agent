# 项目历程：从“AI 工作台”到“官方文档知识库 + MCP 智能体”

## 1. 研发环境
- **工作站**：Windows 11 笔记本 + WSL2（Ubuntu，Python 3.12，uv）
- **服务器**：GCP 雅加达区域一台 Spot 小机（2 vCPU / 6 GB，无 GPU），nftables + fail2ban + CrowdSec + PortSentry 四层防护
- **云服务**：Vertex AI Search（Agent Search，Enterprise + LLM 功能）+ Cloud Storage，费用由 GenAI App Builder 赠金抵扣
- **运维**：cron 每日增量同步；同一来源连续失败 ≥2 次发 Telegram 告警；服务器代码放私有 GitHub 仓库；所有日志带运行 ID
- **本 Demo**：MCP Python SDK 2.x（`MCPServer`）、`google-genai`、`gemini-2.5-flash`

## 2. 参与的 AI 和分工
| 角色 | 职责 |
|---|---|
| 人类负责人 | 所有生产变更都要他批准；架构转向由他拍板；规定“AI 没有分配任务就不准动手” |
| Claude Code（WSL） | 主力建设：服务器初始化、同步管道、`ask` 命令、SSH 门卫、本 MCP + Gemini Demo；每天写日记和回滚恢复点 |
| Codex | 独立**只读验收**：验收发现 4 个真实问题（并发提问证据目录互相覆盖、部分导入失败仍删旧文档、令牌格式校验能被绕过、库外问题判定），已全部修复 |
| Gemini / Grok | 使用方：拿自己的受限钥匙查询知识库，不驻留服务器 |

原则：**稳定优先于能力**。会偏离任务、编造、擅自改默认配置的 AI 再聪明也不能用在共享基础设施上；回答必须以官方文档为依据，是同一原则在“知识”层面的体现。

## 3. 最初的实验方案
- 把 GCP 小机做成多 AI 共用的“AI 工作台”：4 个驻留用户（ai-claude / ai-codex / ai-gemini / ai-grok），共享仓库里各写各的目录，服务器上装 Codex CLI
- 检索走 Google 托管的远程 MCP（Agent Search），各 AI 用自己的身份调用
- 先用 1 个来源（vLLM，75 篇）验证闭环

## 4. 后来的调整和原因
| 调整 | 原因 |
|---|---|
| **AI 不再驻留服务器**：改为一个受限 `kb` SSH 账号（restrict + 强制命令门卫，只能执行 `ask`），删除 4 个 AI 用户和服务器上的 Codex CLI | 每个驻留 AI 都要单独配 Google 身份、令牌刷新、文件权限、仓库钩子；每次说“通了”都得用每个用户的身份重新实测；一次漏配凭据就让 Codex 报未授权、耽误好几个小时。AI 本来就在工作站上登录运行，服务器只需要负责回答问题 |
| **远程 MCP → 服务器端 `ask` 命令**，MCP 放到客户端（就是本 Demo） | 远程 MCP 的 `tools/call` 要给每个身份额外授权（`mcp.toolUser`），403 排查耗时；改用 Agent Search 自带的答案生成后，费用走赠金，**不消耗任何 AI 订阅额度**，4–6 秒出答案 |
| **1 个来源 → 30 个来源、8,530 篇，文档 ID 固定**（来源:路径 的哈希），每日增量同步 | 随机 ID 每次重导都会产生重复文档；ID 固定后上游修改原地覆盖，上游删除同步删除；30 个来源都没变时 7 秒跑完 |
| **服务账号长期密钥 → 每 30 分钟模拟签发 1 小时令牌** | 组织策略禁止创建服务账号密钥；短期令牌本身也更安全 |
| **并行导入 → 拉取/上传并行，导入排队** | 同一数据存储同时只允许一个导入（409） |
| **加 grounding 分数** | `answered=true` 不等于真的覆盖了所问产品，比如 PostgreSQL 复制的问题会“回答”说“没有直接指南” |
| **不装本地模型、不装 Docker** | 2 核 6G 无 GPU 跑不动有用的模型；Docker 的 iptables 规则会和手工维护的 nftables 基线冲突 |
| **打包成 MCP 服务 + Gemini 智能体（本仓库）** | 任何支持 MCP 的客户端（Gemini、Claude Code 等）都能直接接入同一个“只引用官方文档”的工具；`demo` 后端让别人不需要我们的云资源也能跑 |

## 5. 踩过的典型坑（节选）
- cron 的 PATH 不含 `/snap/bin`，令牌刷新一直**静默失败**：cron 里用 snap 程序必须显式设 PATH，并用 `env -i` 模拟 cron 环境实测
- 令牌脚本用了 `2>&1`，gcloud 警告混进令牌文件，导致令牌写进日志：处理凭据的命令一律把 stderr 分开，并校验令牌格式
- 多用户环境只用 root 测通就说“通了”：必须用**实际使用者的身份**实测
